# v2.2 设计 Import 全屏重做 — Design Spec

> **Status:** Approved（用户选 Approach A · mega scope · 5 phase · 1 PR）
> **Branch:** `v2.2-design-import-redesign`（off `v2.1-test-infrastructure` HEAD `e0a246f`）
> **Design source:** `docs/design-imports/V2.2/`（claude.ai/design import · 6 屏 React prototype）
> **Date:** 2026-05-11

## 1. 目标

把 design import 的 6 屏（ProjectList · Wizard · FpEditor · ParamManager · Result · Audit）以**像素级复刻**落到现有 Vue 3 + Pinia 体系，同时**补齐后端**支撑 design 隐含的能力（KPI stats / calc trace / cost composition / AI polling）。一次性发布为 v2.2.0。

**不在 v2.2 范围：**

- 模板与场景（sidebar 标 disabled，等 v2.3）
- 多用户协作 / SSO（v2.x 不动）
- 移动端响应式（design 锁 `width=1440`，本期跟 design 保持桌面 1280+ min-width）

## 2. Scope decisions（已与用户对齐）

### 后端 — calc 返回字段扩展

修改 `schemas/results.py` 的 `ForwardResult`：

```python
class ForwardResult(BaseModel):
    # 现有字段不变
    p10: float
    p50: float
    p90: float
    fp_total: float
    cf: float
    pdr_p50: float
    eff_pm: float
    # v2.2 新增
    trace: PipelineTrace          # 9 步详细
    composition: CostComposition  # 4 段拆分

class PipelineTrace(BaseModel):
    us: float                     # 未调整规模
    cf: float                     # 阶段因子
    s_adjusted: float             # = us × cf
    pdr_p50: float
    dev_factor: float             # 5 项乘积
    eff_pm: float                 # 开发工作量（人月）
    eff_hours: float              # = pm × 176 ≈ 人时
    f_city: float                 # 城市费率
    ops_plus_other: float         # 运维 + 其他
    total_p50: float

class CostComposition(BaseModel):
    dev_labor: float              # 开发人工
    ops_labor: float              # 运维人工
    other: float                  # 其他费
    indirect: float               # 间接/管理（占 1.5% — design 隐含规则）
```

**实现：** `services/calc.py:calc_forward` 已经计算所有数值，只需在 return 处装配 `trace` 和 `composition` dict 即可（无算法改动）。

## 9. FpEditor AI 提取模态（Phase 5.2）

### UX 流程

1. FpEditor 顶栏点 "AI 提取" 按钮 → 检查 `/api/ai-tasks?project_id={id}&status=running`
2. 如有运行中任务 → 直接打开模态对话框展示进度
3. 如无 → 模态对话框显示 "等待 CLI 触发" + 提示文案 "在终端运行 `/cost {id}` 让 Claude 启动提取"
4. 模态对话框每 1.5s polling `/api/ai-tasks/{task_id}` 获取最新进度 + 阶段日志
5. 任务 `status=done` 时，按钮变 "采纳 N 条 FP" — 点击触发 `POST /api/projects/{id}/functions/bulk?source=ai_extracted`

### 后端 — AI Task 表

```python
# db/models.py 新增
class AiTask(Base):
    __tablename__ = "ai_tasks"
    id: Mapped[str] = primary_key (uuid4)
    project_id: Mapped[str] = ForeignKey
    kind: Mapped[str]                  # "extract" | "allocate"
    status: Mapped[str]                # "queued" | "running" | "done" | "failed"
    progress_pct: Mapped[float]        # 0..100
    stage_log: Mapped[str]             # multiline text, append-only
    output_json: Mapped[Optional[str]] # 完成时填，含 87 条 FP draft
    error_message: Mapped[Optional[str]]
    created_at, updated_at
```

### Endpoint

```
POST /api/ai-tasks                     创建任务（CLI 调用）
GET  /api/ai-tasks?project_id=X        列出最近 10 条
GET  /api/ai-tasks/{task_id}           获取 1 条最新状态
PATCH /api/ai-tasks/{task_id}          CLI 上报进度（auth via existing token）
POST  /api/ai-tasks/{task_id}/adopt    采纳到 functions/bulk
```

CLI side（`plugin/commands/cost.md`）改造：现有 `/cost` 命令在提取过程中每完成一个阶段 PATCH 一次 progress。**v2.2 mega 范围不改 plugin 文件**，只暴露 endpoint；plugin 改造放 v2.3 当作 chore。

> ⚠️ 单方面后端 endpoint 改造意味着 v2.2 模态对话框只能展示"task 不存在 — 等待 CLI 触发"或 polling 已存在 task（手工 INSERT）的进度。**这是 D3 的明确取舍**：v2.2 提供 UI 骨架 + 完整 API，plugin 接入留 v2.3。

## 12. 错误处理

- **Pipeline 缺数据**：`trace=null` 时 PipelineGrid 显示 "请先点 [重新计算]"
- **AI Task 不存在**：模态显示 "等待 CLI 触发" + 灰色 disabled "采纳" 按钮
- **stats endpoint 失败**：KPI cards 显示 skeleton + retry 按钮
- **Timeline empty**：显示 EmptyState（已有）"暂无审计事件"
- 所有 API 错误走现有 `client.ts` 的 `useApi` composable，统一 ErrorBanner 顶部提示
