## 4. Phase A — Plugin AI 接入（5 task）

### A1 — `commands/cost.md` 加 begin/stage/end PATCH

`/cost <project_id>` 触发后，按以下时间线上报 AiTask 进度：

```
T0: POST /api/ai-tasks {project_id, kind:"extract"}
    → 拿到 task_id；status=queued, progress=0

T1 (开始解析): PATCH /api/ai-tasks/{id}
    → status=running, progress=10, stage_log_append="✓ 文档解析"

T2 (章节切分): PATCH ... progress=30, stage_log_append="✓ 章节切分"

T3 (类别归类): PATCH ... progress=55, stage_log_append="✓ EI/EO/EQ/ILF/EIF 类别归类"

T4 (写入 FP 表): PATCH ... progress=85, stage_log_append="✓ 写入 FP 表"
    (在此点之前 POST /api/projects/{id}/functions/bulk)

T5 (完成): PATCH ... status=done, progress=100, output_json={...},
    stage_log_append="✓ 完成"
```

如果中途失败：`PATCH ... status=failed, error_message="..."`. 同时给 user 显示文本错误。

**实现细节：**
- `commands/cost.md` 是 markdown 指令文件；改造方式是在原有 "POST /api/projects/{id}/functions/bulk" 步骤前后追加 PATCH 调用指令
- task_id 是 plugin 拿到后自己在 shell variable 持有的（如 `TASK_ID=$(curl ... | jq -r .id)`）
- PATCH 调用失败不阻断主流程（用 `|| true` 兜底；progress 丢失但 FP 提取仍 work）

### A2 — `commands/cost-allocate.md` 同样改造

差异：`kind: "allocate"` 而不是 `"extract"`. 时间线缩短为 4 步:

```
T0: POST kind="allocate"
T1: PATCH progress=20 stage_log="✓ 加载项目反向结果"
T2: PATCH progress=70 stage_log="✓ AI 推荐权重"
T3: PATCH status=done progress=100 output_json={drafts: [...]}
```

### A3 — plugin HTTP flow integration test

新增 `server/tests/integration/test_v2_3_ai_task_plugin_flow.py` —— 模拟 plugin 端的 6 次 PATCH 序列，验证 AiTask record 字段最终态正确。**不是** 真跑 plugin（plugin 是 markdown），而是模拟它会发的 HTTP 调用。

### A4 — e2e `v2.3-ai-task-polling.spec.ts`

测试场景：通过 HTTP API 模拟 plugin 创建 + 推进 task，前端打开 AiTaskModal 应该 polling 到进度。

```
1. 测试 setup: POST /api/ai-tasks {project_id:"p-1", kind:"extract"}
2. Playwright 打开项目，点 ✨ AI 任务 按钮
3. 断言 modal 显示 task_id 前缀
4. 后台 PATCH progress=50
5. 等 polling tick (1.5s+)，断言 progress bar 显示 50%
6. PATCH status=done
7. 断言 "采纳 FP" 按钮出现
```

## 5. Phase B — AI Allocator UI（4 task）

### B1 — `AllocatorPanel.vue` 组件

新组件 `web/src/components/result/AllocatorPanel.vue`. 设计参考 `docs/design-imports/V2.2/project/src/screens-result.jsx:228-271`。

```
┌─ AllocatorPanel 内部结构 ──────────────────────────┐
│ [+ 新增模块]                                       │
│                                                    │
│ 模块名      权重 (滑块)    锁定 FP      操作       │
│ 前端        ███ 1.0       _____       [删]        │
│ 后端        █████ 1.5     _____       [删]        │
│ 数据库      ██████ 2.0    33.0        [删]        │
│                                                    │
│ [✨ 生成分摊]                                      │
│                                                    │
│ ───── 分摊结果（生成后才显示） ─────              │
│ 模块名      权重    分配 FP      类别分布          │
│ 前端        1.0     50.5         [EI][EQ]         │
│ ...                                                │
│                                                    │
│ ✓ 双向一致性校验通过 误差 0.31% ≤ 1%               │
└────────────────────────────────────────────────────┘
```

**props：**

```ts
defineProps<{
  reverseResult: ReverseResult;
  projectId: string;
}>();

const emit = defineEmits<{
  "allocated": [results: AllocateOutput[]];
}>();
```

**内部 state：**

```ts
const drafts = ref<DraftRow[]>([
  { name: "前端", weight: 1 },
  { name: "后端", weight: 1.5 },
]);
const allocResult = ref<AllocateOutput[]>([]);
const allocating = ref(false);
const hint = ref("");
```

**核心交互：**

- "+ 新增模块" → `drafts.value.push({ name: "新模块", weight: 1 })`
- 删除 → `drafts.value.splice(idx, 1)`
- 权重滑块 → 直接 v-model 绑定到 `drafts[i].weight`
- "生成分摊" → 调用 `calcApi.allocate({ project_id, target_us, cf, drafts })`，同 ResultView 现有逻辑

### B2 — ResultView 接入 `AllocatorPanel`

在 ResultView reverse 分支替换现有 `window.prompt` 逻辑：

**删除：**
```ts
async function onAllocate() {
  ...
  const draftsInput = window.prompt("...");
  ...
}
```

**替换为：**

```vue
<AllocatorPanel
  v-if="reverseResult && project"
  :reverse-result="reverseResult"
  :project-id="projectId"
  @allocated="onAllocResult"
/>
```

```ts
function onAllocResult(results: AllocateOutput[]) {
  allocResult.value = results;
}
```

旧的"输入 drafts JSON" prompt 逻辑全部移除（约 -50 行）。

### B3 — 双向一致性 banner（新组件 → 计算并展示反算误差）

设计原型 `screens-result.jsx:269` 显示：

```
✓ 双向一致性校验通过 · forward(分摊后)=¥1,473,164 元 / 目标 ¥1,500,000 元 · 误差 0.31% ≤ 1%
```

放到 AllocatorPanel 内部，在 alloc 完成后显示。误差计算公式：

```
allocated_total_us = sum(allocResult.map(r => r.us))
forward_estimated_total = allocated_total_us / cf * pdr_p50 * f_city / hours_per_pm
error_pct = abs(forward_estimated_total - target_total) / target_total * 100
```

但这要求前端有 `pdr_p50` / `f_city` / `hours_per_pm` —— 这些是 backend params。最简化方案：**后端 calc service 返回时直接给一致性数据**。

方案 B3 修改：

- 后端 `core/allocator.py` 在 `allocate()` 输出末尾加 `validation_error_pct: float` 和 `forward_recalc_total: float`
- 前端从 `calcApi.allocate()` 拿到这两个字段直接显示

如果 `calcApi.allocate()` 返回类型不是 `AllocateOutput[]` 而是 `{ items, validation }` envelope，需要新加 wrapper schema。简化：返回 type 从 `AllocateOutput[]` 升级为 `AllocateResult = { items: AllocateOutput[], validation: { error_pct: number, recalc_total: number } }`。

## 8. 数据流

```
Plugin /cost <id>:
  curl POST /api/ai-tasks {project_id, kind:"extract"} → TASK_ID
  [parse doc...]
  curl PATCH /api/ai-tasks/$TASK_ID {progress:30, stage_log:"✓..."}
  ...
  curl POST /api/projects/{id}/functions/bulk {fps}
  curl PATCH /api/ai-tasks/$TASK_ID {status:"done", progress:100, output_json}

Web AiTaskModal:
  every 1.5s → GET /api/ai-tasks?project_id=X → render task
  on status=done → show "采纳 FP" button

ResultView reverse + AllocatorPanel:
  drafts 数组 (state) ─┐
                       ├─→ POST /api/calc/allocate {project_id, target_us, cf, drafts}
                       └─→ AllocateResult { items, validation }
                            ├─→ allocated table
                            └─→ "误差 X%" 一致性 banner
```

## 9. 错误处理

- **Plugin PATCH 失败** → `|| true` 兜底，主流程不中断。Modal 显示 stuck on 上次 progress；用户可手动重跑 /cost
- **AllocatorPanel 生成失败** → 在面板内显示 `hint` 文本，不弹 alert
- **drafts 为空数组** → "生成分摊" 按钮 disabled
- **legacy e2e flaky** → C1 通过宽松断言 + cleanup 兜底
