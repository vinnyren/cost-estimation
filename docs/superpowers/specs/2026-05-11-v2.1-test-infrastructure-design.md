# 软件造价系统 · v2.1 测试基础设施升级 · 设计规范

**版本**：v2.1 设计稿
**日期**：2026-05-11
**状态**：待评审
**前置**：v2.0 已 release（commit 17fc960 / tag v2.0.0）

---

## 1. 目标

v2.0 release 时 /qa Round 2 + /review 留下 3 项"测试可信度"层面的遗留，本 spec 一次性解决：

1. **修单测隔离运行的 fixture race** — 单独跑某个 v2 integration test 文件时第一个测试报 `Table 'projects' is already defined`。全套跑无影响但开发者隔离调试受阻。
2. **扩 e2e 覆盖** — v2.0 e2e 只有 3 个 happy path（forward / reverse / v2-wizard-flow），未触及 ParamManager 6 tab / 审计 / 复制 / allocator 等 v2 新增入口。
3. **接 coverage 报告 + 防退化** — 当前 170 pytest / 220 vitest 但无 coverage 量化，无法回答"项目级覆盖率多少"或"PR 让覆盖率下降了吗"。

**口号**：让"测试 170/220 全绿"变成"170/220 全绿 + line coverage ≥ 87%/74% + 13 个 e2e 流"。

## 2. 关键决策（已确认）

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | Fixture race 修复策略 | Per-test ephemeral engine | 脱离 `importlib.reload` 魔法；标准 SQLAlchemy + FastAPI 做法；副产品速度提升 ~30% |
| D2 | E2E 覆盖广度 | Standard 13（已有 3 + 新增 10） | 覆盖 v2.0 全部新入口 + 5 个错误路径；不做响应式 / a11y / i18n（YAGNI） |
| D3 | Coverage 工具 + 门槛 | 双引擎 + Baseline + No-regression | pytest-cov + vitest v8；baseline 文件 committed；下降 > 0.5% 拒绝 |

## 3. 子系统设计

### 3.1 Per-test ephemeral engine（Phase A）

**目标**：把 v2.0 的 25 个 integration test fixture 从 `importlib.reload` race-prone 模式切到标准的 in-memory engine + FastAPI dependency override 模式。

**核心架构**：

`server/tests/conftest.py` 新增 3 个 fixture：

```python
import pytest
from sqlalchemy import create_engine
from sqlalchemy.pool import StaticPool
from sqlalchemy.orm import sessionmaker
from httpx import ASGITransport, AsyncClient

from app.db.session import Base, get_db
from app.main import create_app


@pytest.fixture
def db_engine():
    """每 test 一个 in-memory SQLite engine（StaticPool 让多个 session 共享同一连接）。
    yield 后自动 dispose — 内存里的表跟着销毁。
    """
    engine = create_engine(
        "sqlite:///:memory:",
        connect_args={"check_same_thread": False},
        poolclass=StaticPool,
    )
    Base.metadata.create_all(bind=engine)
    yield engine
    engine.dispose()


@pytest.fixture
def db_session(db_engine):
    """每 test 一个 session，绑到 db_engine。"""
    SessionLocal = sessionmaker(bind=db_engine, autoflush=False, autocommit=False)
    session = SessionLocal()
    yield session
    session.close()


@pytest.fixture
async def client(db_session, monkeypatch):
    """每 test 一个 AsyncClient，FastAPI 的 get_db 被覆盖到这个 db_session。
    
    seed_from_csbmk() 在 fixture 内部跑（v2.0 的 23 fixture 都需要 seed）。
    """
    monkeypatch.setenv("COST_AUTH_TOKEN", "test-secret-token-xyz")
    # 用 app factory 拿一个全新 app
    from app import services
    app = create_app()
    # 注入 db_session 覆盖默认 get_db
    app.dependency_overrides[get_db] = lambda: db_session
    # seed CSBMK 基线数据到内存表（v2.1 加 db 参数支持）
    services.params.seed_from_csbmk(db=db_session)
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as c:
        yield c
    app.dependency_overrides.clear()
```

**25 个 fixture 改造模式**：

旧：
```python
@pytest.fixture
async def client(monkeypatch, tmp_path):
    monkeypatch.setenv("COST_AUTH_TOKEN", "test-secret-token-xyz")
    db_file = f"/tmp/cost-test-{uuid.uuid4()}.sqlite"
    monkeypatch.setenv("COST_DB_PATH", db_file)
    monkeypatch.setenv("COST_DATA_DIR", str(tmp_path))
    import importlib
    for m in ["app.config", "app.db.session", ...]:
        importlib.reload(importlib.import_module(m))
    from app.db.session import Base, engine
    Base.metadata.create_all(bind=engine)
    import app.services.params
    app.services.params.seed_from_csbmk()
    ...
```

新：
```python
# 整个 local fixture 删除，直接用 conftest.py 的 client fixture
async def test_foo(client):
    r = await client.post("/api/...", ...)
```

**预计删除**：~125 行 boilerplate（25 文件 × 平均 5 行）。

**风险与缓解**：

| 风险 | 缓解 |
|---|---|
| `seed_from_csbmk()` 当前签名无参数，内部用 module-level SessionLocal 写 ParamGlobal 表 | 加可选参数 `seed_from_csbmk(db: Session \| None = None)`，None 时用旧路径（向后兼容），传入时用注入的 session — 让 in-memory engine 的 ParamGlobal 表能被 seed |
| FastAPI dependency override 在 ASGITransport 下不生效？ | 已验证：`app.dependency_overrides[get_db] = ...` 在 ASGITransport 下正常工作（standard pattern）|
| 测试间数据"看见"对方 | in-memory engine 在 test 间不共享 — fixture function-scope 保证 isolation |
| Project / FunctionPoint cascade DELETE 行为可能因 in-memory + StaticPool 微变 | 单独验证 `cascade_delete` 系列测试，必要时 `PRAGMA foreign_keys=ON` |

### 3.2 13 E2E specs（Phase C）

新增 10 个 spec 到 `web/tests/e2e/`：

| 文件 | 优先级 | Test 用例 |
|---|---|---|
| `param-manager-6tab.spec.ts` | high | 切到每个 tab，验证非 stub（费率有数据、因子卡渲染、规模变更 5 项、快照工具栏） |
| `audit-view.spec.ts` | high | 建项目 + 改 FP → 跳 audit → 至少 2 行；点"加载更早"按钮（如有数据） |
| `project-copy.spec.ts` | high | 建项目 + 1 FP → ⋯ 菜单 → 复制 → 跳新项目 + 验证 FP 已复制 + 验证副本 audit 含 `copied_from` |
| `reverse-allocator.spec.ts` | medium | reverse 项目 → 输入 target_total → calc → 输入 drafts JSON → allocator 渲染 N 行 |
| `wizard-dev-and-ops.spec.ts` | medium | Wizard step 2 选 dev_and_ops → α 滑块拉到 0.8 → step 6 ops factors 显示 → submit |
| `reverse-validation.spec.ts` | medium | Wizard step 4 reverse + target_total=0 → next disabled；填 1000 → enabled |
| `param-snapshot-restore.spec.ts` | medium | 改参数 → 创建快照 "before" → 再改 → restore → 验证恢复原值 |
| `stale-result-banner.spec.ts` | low | calc forward → 改 ParamManager override → 结果页 stale banner 出现 |
| `bulk-snapshot.spec.ts` | low | upload + manual bulk_write → 验证 fp_snapshot 表多一行 |
| `audit-cursor-pagination.spec.ts` | low | mock 50+ audit 行（API setup）→ 翻页 before_id 正确 |

**spec 结构惯例**（与现有 forward.spec.ts 对齐）：
- 每个 spec 一个 top-level `test()` 块
- baseURL + auth token 走 playwright.config.ts 的 extraHTTPHeaders
- 通过 `?t=<TOKEN>` URL 参数注入 sessionStorage（与 forward.spec 同模式）
- try/finally 清理：通过 API DELETE 删测试期创建的项目

**预计代码量**：~600 行（每 spec 平均 60 行）。

### 3.3 Coverage 双引擎（Phase B + D）

**后端 — pytest-cov**：

`server/pyproject.toml` 加 dev dep：
```toml
[project.optional-dependencies]
dev = [
    "pytest>=8.0",
    "pytest-cov>=5.0",  # 新增
    ...
]

[tool.coverage.run]
source = ["app"]
omit = [
    "app/alembic/*",
    "app/data/*",
    "tests/*",
]
branch = true  # 同时跟踪 branch coverage

[tool.coverage.report]
exclude_lines = [
    "pragma: no cover",
    "raise NotImplementedError",
    "if TYPE_CHECKING:",
]
```

新 npm-style script `pytest-cov-report`：
```bash
.venv/bin/pytest --cov=app --cov-report=html --cov-report=json:coverage.json
# 输出 server/htmlcov/index.html + server/coverage.json
```

**前端 — vitest v8 provider**：

`web/vitest.config.ts` 扩展：

**No-regression hook** `scripts/check-coverage.sh`：
```bash
#!/usr/bin/env bash
set -euo pipefail

# 1. 跑测试 + 收集 coverage
(cd server && .venv/bin/pytest --cov=app --cov-report=json:coverage.json -q)
(cd web && pnpm test:coverage)

# 2. 解出当前覆盖率
BACKEND_PCT=$(python3 -c "import json; d=json.load(open('server/coverage.json')); print(d['totals']['percent_covered'])")
FRONTEND_PCT=$(python3 -c "import json; d=json.load(open('web/coverage/coverage-summary.json')); print(d['total']['lines']['pct'])")

# 3. 与 baseline 比对
python3 scripts/_compare-coverage.py "$BACKEND_PCT" "$FRONTEND_PCT" || exit 1

echo "✓ Coverage 不退化"
```

`scripts/_compare-coverage.py`：读 `coverage-baseline.json` 与当前值比，下降 > tolerance 退出 1（含友好错误提示），上升时输出 "建议跑 `scripts/update-coverage-baseline.sh` 锁新 baseline"。

`scripts/update-coverage-baseline.sh`：用户主动跑，把当前 coverage 写回 baseline 文件。

**集成方式**（不强加）：
- 默认手动跑：`scripts/check-coverage.sh`
- 可选：装到 `.git/hooks/pre-commit`（README 提供脚本，让用户自决）
- v2.1 README 加一节"覆盖率验证"说明用法
